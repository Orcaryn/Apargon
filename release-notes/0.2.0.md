### Security

- A page with `papp-net` can no longer reach your local network through a name or a wildcard: private addresses, VPN ranges such as Tailscale's, and the link-local address where cloud machines keep their keys are refused, as was this computer already. So a server cannot point a name you approved at your network. Only a device the tag names by its address in numbers is reached, and its line is red. A tag that names this computer's other addresses or the link-local range is refused before the popup, and a tag that names a public address is red.
- A red line, or lines that together can send your files out, now need the checkbox wherever the page came from. Before, only a page marked as downloaded did, but `git clone`, `curl` and USB sticks leave no mark.
- A downloaded page with no tags is now asked about once, so you see its site before it reads the folder it landed in.
- An approval of a downloaded page now covers its exact content: if the page changes, Apargon asks again and says so.
- One page can no longer read what another kept in `localStorage`, IndexedDB or the cache.
- A frame in a page can no longer load another file, and a link to another file does not open: that file would run with the page's permissions.
- Only tags in `<head>` before the first `<script` or `<body`, outside comments, count.
- macOS: a page opens only once the sandbox has proved it is on. Before, a check that failed for any other reason counted as proof.
- macOS: programs a page runs can no longer script other apps (`osascript`, Apple Events).
- macOS: a page's programs can no longer get a system service to fetch a certificate's issuer for them from outside the sandbox.
- Linux: a page and its programs no longer see `/run`, `/tmp` or `/var/tmp`, which hold sockets to programs outside the sandbox: D-Bus, the name lookup service, the sound server, tmux, screen and Docker. Only the display's socket and what the tags name come back.
- Linux: a page and its programs can no longer make namespaces of their own, which most Linux privilege escalations need, and see only the GPU in `/dev`, not the disks, and the camera or the microphone only with a tag. `papp-use sound` brings back the sound devices, so a program the page runs can record from the microphone too.
- Linux: a program a page runs can no longer read the environment Apargon was started with through the page's process.
- Linux: two pages open at once can no longer use each other's declared servers.

### New

- `papp-use` lets a page do one more thing, one value per tag: `notifications` (shown through `papp.notify`), `clipboard` (read it from code; a paste you make always worked), `location` (macOS), `sound`, `camera` and `microphone` (for recorders, dictation and webcam tools) and `screen` (the whole main screen through `getDisplayMedia`; not on Wayland). Clipboard, location, camera and microphone show yellow and screen red, and with `papp-net` the popup says what can be sent. On macOS the system also asks the first time a page uses the location, the camera, the microphone or the screen.
- `papp-shortcut` names a key combination the page answers in every app, such as `CommandOrControl+Shift+N`. It needs two different modifiers, or one with a function key, so a page cannot take `Ctrl+C` from the app in front, and not only modifiers that type characters, such as Option+Shift on macOS. Pressing it brings the page to the front.
- A page can open a second window of itself with `window.open('#name')`. Other files and sites still do not open.
- `papp.spawn` runs a program for a long job: the page gets its output as it comes, can write to it, and can stop it. It stops when the page closes or reloads.
- `papp.tray(title)` puts Apargon's icon in the menu bar, with a short text beside it on macOS; on Linux the icon's tooltip names the page instead. A click brings the page to the front.
- `papp-socket` names a socket file, or a folder of them, that the page and its programs may connect to. It is always red: what answers there runs outside the sandbox.
- A page can talk to a device on your local network, such as a smart-home hub, a NAS or a router, if it names it by its address in numbers and one port: `192.168.1.5:8123`. The line is red, because Apargon cannot tell what answers there.
- A page with a favicon shows it as its icon, with Apargon's badge on the corner: in the Dock and the app switcher on macOS, as its window icon on Linux. On macOS a page made on this computer also gets it as its icon in Finder.

### Changed

- A page plays sound only with `papp-use sound`. Without it the window is muted, on macOS too, so the tag means the same everywhere. On Linux the tag brings the sound server back into the sandbox.
- resworb is now Apargon. Rename each page from `.lmth` to `.papp` and each tag from `resworb-*` to `papp-*`, and use `window.papp` instead of `window.resworb`. Approvals do not carry over, so Apargon asks again about each page with tags, and pages start with empty storage.
- macOS: resworb 0.1.1 cannot update itself to Apargon. Download Apargon from this release, then delete resworb from Applications.
- Linux: install the `apargon` package, then `sudo apt remove resworb`. It needs bubblewrap 0.8.0 or later; Ubuntu 24.04 has it.
- Linux: a `papp-read` or `papp-write` that would open `/tmp`, `/var/tmp`, anything at or under `/run`, or a folder holding one such as `/`, is refused. So is a page that sits in one of them. Move the files elsewhere.
- A `papp-net` tag that names a device on your local network by name, such as `nas.local:5000`, no longer connects. Name it by its address in numbers instead, such as `192.168.1.5:5000`.
- A tag after the first `<script` or `<body`, or inside a comment, is no longer read. Move it into `<head>` before any script.
