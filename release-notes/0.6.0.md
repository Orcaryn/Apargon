### Security

- macOS: a `.papp` file's name lookups could leave the computer through the system's resolver. Every name now goes to the proxy, which looks up only allowed sites.
- Linux: Chromium looks up no name itself, as on Windows. Every name goes to the proxy.
- Linux: a program could make the computer look up a name through the keyring calls. They're refused now.
- The proxy refuses a name that leads to a cloud computer's metadata server.
- The proxy refuses to reach its own port, however `localhost` is written (`LOCALHOST`, `localhost.`).
- A `.papp` file can no longer read Apargon's secrets folder, on every OS.
- Approval popups stay above a `.papp` file's on-top windows, which could cover them before.
- When a different file uses a `papp-id` that another `.papp` file already opened with, the popup warns and names the other file.
- A `papp-write` folder inside a cloud folder needs `papp-use cloud`. Under `papp-write all`, cloud folders stay off-limits without it.
- macOS: with your home folder on an external disk, a `.papp` file could read your cloud folders, and write them under `papp-write all`. It can't now.
- macOS: the sandbox also blocks automounts, broadcasts to other apps, fake input and launch jobs. Camera and microphone stay off without their `papp-use` tag.
- macOS: programs get no system services but the GPU's shader compiler, no kernel control sockets and no device setting writes.
- Linux: `autofs` mounts are hidden, like network drives.
- Windows: OneDrive is denied, not only skipped, unless `papp-use cloud`.
- Windows: the sandbox can no longer write your temp folder. A `.papp` file could put a program there, have you approve it with `papp-run unfenced`, then swap it.
- A `.papp` file can't write through a pick into the folder of a `papp-run unfenced` program.
- `SECURITY.md` now names these gaps:
  - Cloud folders on Linux, and other sync apps' folders on Windows, aren't blocked.
  - Linux: `papp-socket` turns off the `io_uring` and keyring blocks too.
  - Linux without a keyring: secrets are encrypted with a fixed key.

### New

- `papp.env(name)` reads a `papp-env` variable. `papp-env` no longer needs `papp-run`.
- A `.papp` file with only `papp-id`, `papp-window`, `papp-use notifications` or `sound`, a sandboxed `papp-run` or `papp-env` opens with no popup.
- When the popup asks again, it marks the new lines, and a **Trust changes to this file** checkbox keeps your yes when the file's bytes change.
- A `.papp` file that changes while open shows a **Restart** button. A file that opened without a popup, or whose changes you trust, reloads until what it asks for changes.
- Windows: `papp-use bluetooth`.
- macOS: programs can use the GPU.
- The papp skill you installed updates itself with Apargon.

### Changed

- A `.papp` file that still gets a popup asks again once if it has `papp-window`, `papp-use notifications` or `sound`, `papp-env`, or on macOS `papp-socket`: its popup lines changed.
- A `papp-write` folder inside iCloud Drive, Dropbox or OneDrive is refused until you add `<meta name="papp-use" content="cloud">`.
- The **Show Egress Log** menu item is gone.

### Fixed

- `papp.connect` sockets close as soon as what was written is sent, not up to five seconds later.
- `install.sh` on Windows now points you to the `.exe`.
